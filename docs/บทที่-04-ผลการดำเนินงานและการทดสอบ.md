# บทที่ 4 ผลการดำเนินงานและการทดสอบ

## 4.1 บทนำ

บทนี้นำเสนอผลการพัฒนาระบบที่ได้จริง องค์ประกอบของระบบหลังติดตั้ง และแผนการทดสอบเพื่อยืนยันว่าโปรเจคทำงานครบวงจรตามวัตถุประสงค์

> หมายเหตุสำหรับผู้จัดทำเล่ม: ควรแทรกรูปถ่ายชุดสายพานจริง, หน้าจอ Serial Monitor, หน้า Node-RED, หน้า Grafana และตารางผลทดลองจากวันสาธิตจริงลงในหัวข้อ 4.2–4.5

## 4.2 ผลการพัฒนาระบบโดยรวม

ระบบที่พัฒนาเสร็จแล้วประกอบด้วย 4 ส่วนหลักที่ทำงานร่วมกัน:

1. **ชุดฮาร์ดแวร์ ESP32 + IR 3 จุด** สามารถนับ Total / Good / Waste และส่งขึ้นคลาวด์ได้
2. **ระบบหลังบ้าน Node-RED** คำนวณ OEE และตรวจจับสถานะ IDLE อัตโนมัติ
3. **ฐานข้อมูล InfluxDB** เก็บค่าตัวชี้วัดแบบอนุกรมเวลา
4. **Grafana Dashboard** แสดงสถานะเครื่อง เกจ OEE และแนวโน้มการผลิต

ผลลัพธ์สำคัญคือผู้ใช้สามารถมองเห็นการเปลี่ยนแปลงของยอดนับและค่า OEE ได้แบบเรียลไทม์เมื่อมีชิ้นงานไหลผ่านสายพาน

## 4.3 ผลการทำงานฝั่งฮาร์ดแวร์

เมื่อวัตถุตัดผ่านเซนเซอร์แต่ละตัว ระบบแสดงผลดังนี้:

| เหตุการณ์ | ผลลัพธ์ที่เกิดขึ้น |
| --- | --- |
| ผ่านเซนเซอร์ Total (ต้นสาย) | ค่า `total` เพิ่มขึ้น และถูก publish ไปยัง topic ที่เกี่ยวข้อง |
| พนักงาน QC จับชิ้นงานเสียให้โดนเซนเซอร์กลาง (Manual QC) | ค่า `waste` เพิ่มขึ้น |
| ผ่านเซนเซอร์ Good (ปลายสาย) | ค่า `good` เพิ่มขึ้น |
| สัญญาณกระตุกสั้น ๆ | ถูกกรองด้วย debounce ทำให้ไม่นับซ้ำง่าย |

นอกจากนี้ firmware มีการตรวจสอบการเชื่อมต่อ MQTT เป็นระยะ หากขาดการเชื่อมต่อจะพยายามเชื่อมใหม่โดยอัตโนมัติ

## 4.4 ผลการทำงานฝั่งซอฟต์แวร์และ Dashboard

### 4.4.1 Node-RED
- รับค่าจาก MQTT ได้ครบ 3 topics
- อัปเดตค่าทุก 1 วินาที
- คำนวณ Availability, Performance, Quality และ OEE ได้ต่อเนื่อง
- เมื่อไม่มีชิ้นงานเกิน 1 นาที สถานะเปลี่ยนเป็น IDLE
- เมื่อมีชิ้นงานผ่านอีกครั้ง สถานะกลับเป็น RUNNING

### 4.4.2 InfluxDB
ข้อมูลถูกบันทึกใน measurement `oee_metrics` ภายใต้ bucket `conveyor_oee` ทำให้สามารถเรียกดูประวัติย้อนหลังได้

### 4.4.3 Grafana
Dashboard แสดงผลได้ครบกลุ่มหลัก:
- สถานะเครื่องจักรและ Running Time
- เกจ OEE / Availability / Performance / Quality
- ยอดผลิต Total / Good / Waste
- กราฟแนวโน้มจำนวนชิ้นงาน

## 4.5 แผนการทดสอบระบบ

| รหัส | หัวข้อทดสอบ | วิธีการ | ผลที่คาดหวัง | ผ่าน/ไม่ผ่าน |
| --- | --- | --- | --- | --- |
| T01 | นับ Total | ปล่อยชิ้นงานผ่าน IR ต้นสายพาน | ค่า total เพิ่มใน Dashboard |  |
| T02 | นับ Waste (Manual QC) | พนักงานจับชิ้นงานเสียให้โดน IR กึ่งกลาง | ค่า waste เพิ่ม |  |
| T03 | นับ Good | ปล่อยชิ้นงานดีผ่าน IR ปลายสายพาน | ค่า good เพิ่ม |  |
| T04 | ส่ง MQTT | ดูค่าที่ Node-RED / Debug | มีข้อความเข้าตาม topic |  |
| T05 | คำนวณ Quality | เปรียบเทียบ good/total | ค่าคุณภาพสอดคล้องกับยอดนับ |  |
| T06 | Idle Watchdog | หยุดไม่ให้มีชิ้นงาน > 60 วินาที | สถานะเป็น IDLE |  |
| T07 | Resume Running | มีชิ้นงานผ่านหลัง IDLE | สถานะกลับ RUNNING |  |
| T08 | บันทึก InfluxDB | ตรวจข้อมูลใน bucket | มีจุดข้อมูลใหม่ตามเวลา |  |
| T09 | Grafana Refresh | สังเกตเกจและกราฟ | ค่าบนจออัปเดตตามข้อมูลจริง |  |
| T10 | Reconnect | ตัด/ต่อ Wi-Fi ชั่วคราว | ระบบพยายามเชื่อมต่อกลับ |  |

## 4.6 เกณฑ์ความสำเร็จของโปรเจค

ถือว่าโปรเจคสำเร็จเมื่อครบเงื่อนไขต่อไปนี้:

1. สาธิตการไหลข้อมูลจากเซนเซอร์ถึง Dashboard ได้แบบ end-to-end
2. ค่า OEE ทั้ง 3 องค์ประกอบแสดงผลได้และอธิบายที่มาได้
3. ระบบเปลี่ยนสถานะ IDLE/RUNNING ตามเงื่อนไขเวลาได้
4. ข้อมูลถูกบันทึกและเรียกดูย้อนหลังผ่าน Grafana ได้
5. มีเอกสารประกอบการติดตั้งและอธิบายระบบครบถ้วน

## 4.7 ปัญหาที่พบระหว่างพัฒนาและแนวทางแก้ (ตัวอย่างกรอบเขียน)

| ปัญหา | สาเหตุที่เป็นไปได้ | แนวทางแก้ไข |
| --- | --- | --- |
| นับชิ้นงานซ้ำ | สัญญาณเซนเซอร์กระตุก | ปรับค่า debounce และตรวจขอบสัญญาณ |
| MQTT ต่อไม่ติด | credentials/hostname ผิด หรือเน็ตไม่เสถียร | ตรวจค่าตั้งต้นและสถานะ TLS |
| OEE เพี้ยนตอนเครื่องหยุด | ยังนับว่าเครื่องวิ่งทั้งที่ของไม่ไหล | เพิ่ม Watchdog 60 วินาที |
| Dashboard ไม่ขึ้นกราฟ | ชื่อ bucket/field ไม่ตรง | ตรวจ measurement และ query ใน Grafana |

> ผู้จัดทำควรเติมปัญหาจริงที่เจอระหว่างทำชุดสาธิตลงตารางนี้ เพื่อให้บทที่ 4 มีน้ำหนักเชิงปฏิบัติ

## 4.8 สรุปบทที่ 4

ผลการดำเนินงานแสดงว่าระบบสามารถเชื่อมโยงฮาร์ดแวร์กับการประมวลผลและ Dashboard ได้ตามที่ออกแบบ โดยมีแผนทดสอบครอบคลุมทั้งการนับชิ้นงาน การคำนวณ OEE การเปลี่ยนสถานะเครื่อง และการแสดงผลแบบเรียลไทม์ ซึ่งพร้อมใช้เป็นหลักฐานตอนสอบและสาธิตโปรเจค
