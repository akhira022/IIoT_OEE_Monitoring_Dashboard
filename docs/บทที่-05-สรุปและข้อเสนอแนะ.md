# บทที่ 5 สรุป อภิปรายผล และข้อเสนอแนะ

## 5.1 สรุปผลการดำเนินงาน

โปรเจคระบบตรวจสอบประสิทธิภาพสายพานลำเลียงอัจฉริยะด้วยสถาปัตยกรรม IIoT และดัชนี OEE สามารถพัฒนาจนใช้งานในลักษณะชุดสาธิตได้ครบวงจร โดยมีองค์ประกอบหลักดังนี้

1. ฮาร์ดแวร์ ESP32 ร่วมกับเซนเซอร์ IR 3 จุด สำหรับนับ Total (ต้นสาย), Waste แบบ Manual QC (กลางสาย), และ Good (ปลายสาย)
2. การสื่อสารข้อมูลผ่าน MQTT ไปยังระบบคลาวด์
3. การคำนวณ OEE และตรวจจับสถานะ IDLE ที่ Node-RED
4. การจัดเก็บข้อมูลใน InfluxDB และการแสดงผลบน Grafana

ระบบตอบวัตถุประสงค์หลักของโปรเจค คือทำให้เห็นสถานะการผลิตและตัวชี้วัดประสิทธิภาพแบบเรียลไทม์ แทนการพึ่งพาการจดบันทึกด้วยมือเพียงอย่างเดียว

## 5.2 อภิปรายผล

### 5.2.1 จุดที่ทำได้ดี
- สถาปัตยกรรมแยกชั้นชัดเจน อธิบายและสาธิตง่าย
- ใช้ตัวชี้วัด OEE ซึ่งเป็นมาตรฐานในงานผลิตจริง
- มีทั้งข้อมูลปัจจุบันและแนวโน้มย้อนหลัง
- เหมาะกับระดับ ปวส. เพราะฮาร์ดแวร์ไม่ซับซ้อนเกินไป แต่ความรู้ที่ได้อครอบคลุมหลายวิชา

### 5.2.2 ข้อจำกัดของระบบ
- เป็นชุดสาธิต จึงยังไม่เทียบเท่าความทนทานของระบบโรงงานจริง
- Ideal Cycle Time ถูกกำหนดคงที่ที่ 5 วินาที/ชิ้น ซึ่งอาจไม่เหมาะกับทุกชนิดงาน
- คุณภาพชิ้นงานขึ้นกับการจัดวางเซนเซอร์และการคัดแยก ไม่ได้ใช้ระบบวิชันซิสเต็ม
- การทำงานพึ่งพาอินเทอร์เน็ตคลาวด์ หากเครือข่ายขัดข้อง ข้อมูลจะสะดุด
- ยังไม่มีระบบแจ้งเตือนเหตุการณ์และการจัดการผู้ใช้แบบสมบูรณ์

### 5.2.3 บทเรียนที่ได้
การทำระบบ IIoT ให้สำเร็จไม่ได้จบที่การอ่านเซนเซอร์ได้อย่างเดียว แต่ต้องออกแบบการไหลของข้อมูล การกันสัญญาณรบกวน การจัดการสถานะเครื่อง และการสื่อสารผลลัพธ์ให้ผู้ใช้เข้าใจได้ในเวลาอันสั้น

## 5.3 ข้อเสนอแนะในการนำไปใช้

1. ใช้เป็นสื่อสาธิตในวิชา IIoT, ไมโครคอนโทรลเลอร์ หรือระบบอัตโนมัติ
2. ใช้ฝึกนักศึกษาให้แยกวิเคราะห์ปัญหาเครื่องจักรผ่านแกน Availability / Performance / Quality
3. ก่อนนำไปใช้ภาคสนาม ควรสอบเทียบเซนเซอร์และปรับ Ideal Cycle Time ให้ตรงงานจริง
4. ควรแยกเก็บ credentials ออกจากซอร์สโค้ดทุกครั้งที่เผยแพร่โปรเจค

## 5.4 ข้อเสนอแนะเพื่อการพัฒนาต่อ

1. เพิ่มปุ่ม Reset ยอดนับจาก Dashboard
2. เพิ่มการแจ้งเตือนผ่าน LINE หรืออีเมลเมื่อ OEE ต่ำหรือเครื่อง IDLE นานผิดปกติ
3. กำหนดเกณฑ์สีมาตรฐานของค่า OEE เพื่ออ่านผลได้เร็วขึ้น
4. บันทึกสาเหตุการหยุดเครื่อง (Downtime Reason)
5. รองรับหลายสายพานพร้อมกัน
6. พัฒนาโหมดเก็บข้อมูลชั่วคราวตอนเน็ตหลุด แล้วค่อยซิงก์เมื่อกลับมาออนไลน์
7. เพิ่มชั้นความปลอดภัยและการสำรองข้อมูลให้ใกล้ระบบใช้งานจริงมากขึ้น

## 5.5 สรุปท้ายบท

โปรเจคนี้แสดงให้เห็นว่านักศึกษา ปวส. สามารถสร้างต้นแบบระบบ IIoT ที่เชื่อมโยงฮาร์ดแวร์เข้ากับตัวชี้วัดอุตสาหกรรมได้อย่างเป็นรูปธรรม หากพัฒนาต่อในส่วนความเสถียร การแจ้งเตือน และการปรับพารามิเตอร์ให้ตรงหน้างาน ระบบจะยิ่งมีศักยภาพสำหรับการเรียนการสอนและการประยุกต์ใช้ในโรงงานขนาดเล็กได้มากขึ้น
