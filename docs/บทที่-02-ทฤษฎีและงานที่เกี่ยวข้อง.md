# บทที่ 2 ทฤษฎีและงานที่เกี่ยวข้อง

## 2.1 บทนำ

บทนี้นำเสนอทฤษฎีและเทคโนโลยีที่เกี่ยวข้องกับโปรเจค ได้แก่ ดัชนี OEE แนวคิด IIoT โปรโตคอล MQTT ไมโครคอนโทรลเลอร์ ESP32 เซนเซอร์อินฟราเรด Node-RED ฐานข้อมูล InfluxDB และเครื่องมือแสดงผล Grafana เพื่อเป็นพื้นฐานในการออกแบบระบบในบทที่ 3

## 2.2 Overall Equipment Effectiveness (OEE)

OEE หรือประสิทธิผลโดยรวมของเครื่องจักร เป็นตัวชี้วัดที่ใช้ประเมินว่าเครื่องจักรใช้งานได้มีประสิทธิภาพเพียงใด โดยพิจารณา 3 องค์ประกอบหลัก

\[
OEE = Availability \times Performance \times Quality
\]

### 2.2.1 Availability (ความพร้อมใช้งาน)
แสดงสัดส่วนเวลาที่เครื่องจักรพร้อมผลิตจริงเมื่อเทียบกับเวลาที่วางแผนไว้  
ในโปรเจคนี้ประมาณจากเวลาสถานะ RUNNING เทียบกับเวลารวมตั้งแต่เริ่มระบบ

รายละเอียดเพิ่มเติมว่า Planned Time มาจากไหนและคำนวณอย่างไร ดูที่  
[เอกสารพิเศษ-plannedTime-Availability.md](./เอกสารพิเศษ-plannedTime-Availability.md)

### 2.2.2 Performance (สมรรถนะ)
แสดงว่าเครื่องผลิตได้เร็วใกล้เคียงมาตรฐานหรือไม่  
โปรเจคนี้กำหนด Ideal Cycle Time = 5 วินาทีต่อชิ้น แล้วเทียบยอดผลิตจริงกับยอดที่ควรได้ในช่วงเวลาวิ่ง

### 2.2.3 Quality (คุณภาพ)
แสดงสัดส่วนชิ้นงานดีต่อชิ้นงานทั้งหมด

\[
Quality = \frac{Good}{Total} \times 100
\]

### 2.2.4 การแปลผลเบื้องต้น
- OEE สูง หมายถึงเครื่องพร้อม ผลิตทันมาตรฐาน และของเสียต่ำ
- หาก OEE ต่ำ ควรไล่ดูทีละแกนว่าปัญหาอยู่ที่ Availability, Performance หรือ Quality

## 2.3 Industrial Internet of Things (IIoT)

IIoT คือการประยุกต์อินเทอร์เน็ตของสรรพสิ่งในภาคอุตสาหกรรม โดยเชื่อมเซนเซอร์ อุปกรณ์ควบคุม และระบบวิเคราะห์ข้อมูลเข้าด้วยกัน เพื่อมอนิเตอร์และปรับปรุงกระบวนการผลิต

สถาปัตยกรรมทั่วไปที่โปรเจคนี้ใช้มี 5 ชั้น:
1. Device / Edge
2. Connectivity
3. Processing / Logic
4. Storage
5. Visualization

## 2.4 โปรโตคอล MQTT

MQTT (Message Queuing Telemetry Transport) เป็นโปรโตคอลสื่อสารแบบ Publish/Subscribe ที่เบาและเหมาะกับงาน IoT

องค์ประกอบสำคัญ:
- **Publisher:** ฝั่งที่ส่งข้อมูล (ESP32)
- **Broker:** ตัวกลางกระจายข้อความ (HiveMQ Cloud)
- **Subscriber:** ฝั่งที่รับข้อมูลไปใช้ต่อ (Node-RED)

ข้อดีที่เลือกใช้ MQTT ในโปรเจคนี้:
- ขนาดแพ็กเก็ตเล็ก ส่งถี่ได้
- แยก topic ตามชนิดข้อมูลได้ชัด
- รองรับการเชื่อมต่อผ่าน TLS เพื่อความปลอดภัยเบื้องต้น

## 2.5 ไมโครคอนโทรลเลอร์ ESP32

ESP32 เป็นไมโครคอนโทรลเลอร์ที่มี Wi-Fi ในตัว ราคาไม่สูง และรองรับงาน IoT ได้ดี จึงเหมาะกับชุดสาธิตระดับสถานศึกษา

บทบาทในโปรเจค:
- อ่านสัญญาณจากเซนเซอร์ IR
- กันสัญญาณรบกวนด้วย debounce
- เชื่อมต่อ Wi-Fi และส่งค่าขึ้น MQTT

## 2.6 เซนเซอร์อินฟราเรด (IR Sensor)

ใช้ตรวจจับวัตถุที่ตัดผ่านแนวลำแสง เพื่อนับจำนวนชิ้นงาน  
ในระบบกำหนดจุดติดตั้ง 3 จุด:
- Total: ต้นสายพาน
- Good: จุดผ่านงานดี
- Waste: จุดของเสีย

เทคนิคสำคัญที่ต้องใช้คู่กับเซนเซอร์คือ **Debounce** เพื่อลดการนับซ้ำจากสัญญาณกระตุก

## 2.7 Node-RED

Node-RED เป็นเครื่องมือเขียนโปรแกรมเชิงไหล (flow-based) ที่เหมาะกับงานเชื่อมต่ออุปกรณ์และบริการต่าง ๆ  
ในโปรเจคนี้ใช้เพื่อ:
- รับข้อมูลจาก MQTT
- คำนวณ OEE
- ทำ Watchdog ตรวจจับ IDLE
- ส่งข้อมูลเข้า InfluxDB และ UI ทดสอบ

## 2.8 InfluxDB

InfluxDB เป็นฐานข้อมูลเชิงเวลา (time-series database) เหมาะกับข้อมูลเซนเซอร์และตัวชี้วัดที่เปลี่ยนตามเวลา  
โปรเจคนี้ใช้ InfluxDB v2 และ bucket ชื่อ `conveyor_oee` เพื่อเก็บค่า OEE และยอดผลิต

## 2.9 Grafana

Grafana เป็นเครื่องมือสร้าง Dashboard สำหรับมอนิเตอร์ระบบ  
ใช้แสดงเกจ OEE, สถานะเครื่อง, ยอดนับ และกราฟแนวโน้ม ซึ่งสื่อสารผลลัพธ์ได้ดีทั้งตอนสาธิตและตอนสอบ

## 2.10 แนวคิด Watchdog / Idle Detection

หากไม่มีการไหลของชิ้นงานเกินเวลาที่กำหนด ระบบควรปรับสถานะเครื่องเป็น IDLE เพื่อไม่ให้ประเมินว่าเครื่องยังทำงานปกติ  
ในโปรเจคนี้ใช้เกณฑ์ 60 วินาที ซึ่งช่วยให้ค่า Availability และ Performance สะท้อนความเป็นจริงมากขึ้น

## 2.11 สรุปบทที่ 2

ทฤษฎีที่เกี่ยวข้องครอบคลุมทั้งตัวชี้วัดวิศวกรรมอุตสาหการ (OEE) และเทคโนโลยี IIoT ที่ใช้สร้างระบบจริง การทำความเข้าใจแต่ละส่วนจะช่วยให้ออกแบบสถาปัตยกรรมและอธิบายเหตุผลการเลือกใช้เครื่องมือได้อย่างมีหลักการในบทถัดไป
