# บทที่ 3 วิธีการดำเนินงาน

## 3.1 บทนำ

บทนี้อธิบายขั้นตอนการดำเนินงาน การออกแบบสถาปัตยกรรมระบบ ส่วนฮาร์ดแวร์ ส่วนซอฟต์แวร์ และการไหลของข้อมูลของโปรเจคระบบตรวจสอบประสิทธิภาพสายพานด้วย IIoT และ OEE

## 3.2 ขั้นตอนการดำเนินงานโดยรวม

1. ศึกษาปัญหาและกำหนดขอบเขตโปรเจค
2. ศึกษาทฤษฎี OEE และเทคโนโลยีที่เกี่ยวข้อง
3. ออกแบบสถาปัตยกรรมระบบและกำหนด MQTT topics
4. พัฒนา firmware ESP32 สำหรับนับชิ้นงานและส่งข้อมูล
5. พัฒนา Flow ใน Node-RED สำหรับคำนวณ OEE และ Watchdog
6. ตั้งค่า InfluxDB และ Grafana Dashboard
7. ทดสอบระบบแบบครบวงจรและปรับปรุง
8. จัดทำเอกสารรายงานและคู่มือใช้งาน

## 3.3 การออกแบบสถาปัตยกรรมระบบ

```text
IR Sensors (Total/Good/Waste)
        |
        v
     ESP32 (Edge)
        |
   MQTT / TLS :8883
        |
        v
   HiveMQ Cloud (Broker)
        |
        v
     Node-RED
  (OEE + Watchdog)
        |
        +-----> Node-RED Dashboard (ดีบัก)
        |
        v
   InfluxDB v2
 bucket: conveyor_oee
        |
        v
     Grafana
   (Monitor UI)
```

### 3.3.1 หลักการออกแบบ
- แยกชั้น Edge กับ Logic ให้ชัด เพื่อปรับสูตร OEE ได้โดยไม่ต้องแฟลชบอร์ดใหม่บ่อย ๆ
- ใช้ MQTT topics แยกตามชนิดข้อมูล เพื่อง่ายต่อการขยาย
- เก็บข้อมูลแบบ time-series เพื่อวิเคราะห์แนวโน้ม
- แสดงผลด้วยเครื่องมือมาตรฐานอุตสาหกรรมเพื่อการสาธิตที่น่าเชื่อถือ

## 3.4 การออกแบบฮาร์ดแวร์

### 3.4.1 อุปกรณ์หลัก (เวอร์ชัน 8.3)
- ESP32 Development Board
- IR Sensor × 3
- ชุดสายพานจำลอง
- แหล่งจ่ายไฟที่เหมาะสม
- เครือข่าย Wi-Fi 2.4 GHz ที่ออกอินเทอร์เน็ตได้

### 3.4.2 การกำหนดขาพินและตำแหน่งเซนเซอร์

| ตำแหน่งบนสายพาน | อุปกรณ์ | GPIO | หน้าที่ | วิธีนับ |
| --- | --- | --- | --- | --- |
| จุดที่ 1 ต้นสายพาน | IR Sensor Total | 2 | นับชิ้นงานเข้าสู่สายพาน | อัตโนมัติ |
| จุดที่ 2 กึ่งกลางสายพาน | IR Sensor Waste | 5 | นับชิ้นงานเสีย (Manual QC) | พนักงานจับชิ้นงานเสียให้โดนเซนเซอร์ |
| จุดที่ 3 ปลายสายพาน | IR Sensor Good | 4 | นับชิ้นงานดี | อัตโนมัติ |

**กระบวนการ Manual QC:** พนักงาน QC ตรวจสอบชิ้นงานด้วยสายตา หากเป็นของเสียจะจับชิ้นงานให้โดนเซนเซอร์กลางเพื่อบันทึก Waste จากนั้นชิ้นงานดีไหลต่อไปยังปลายสายเพื่อบันทึก Good

### 3.4.3 ตรรกะฝั่งเฟิร์มแวร์
1. อ่านสถานะเซนเซอร์แบบ INPUT_PULLUP
2. ตรวจจังหวะขอบขาลง (Falling Edge) เมื่อวัตถุตัดผ่าน
3. ใช้ debounce ประมาณ 150 มิลลิวินาที
4. เพิ่มตัวนับและ publish ค่าขึ้น MQTT ทันที
5. มีกลไก reconnect Wi-Fi/MQTT เมื่อการเชื่อมต่อหลุด

ไฟล์หลัก: `esp32/esp32_8.3v.ino`

## 3.5 การออกแบบการสื่อสารข้อมูล

### 3.5.1 MQTT Topics

| Topic | ความหมาย |
| --- | --- |
| `factory/conveyor/total` | ยอดนับชิ้นงานรวม |
| `factory/conveyor/good` | ยอดนับชิ้นงานดี |
| `factory/conveyor/waste` | ยอดนับชิ้นงานเสีย |

### 3.5.2 ความปลอดภัยเบื้องต้น
- เชื่อมต่อ HiveMQ Cloud ผ่านพอร์ต 8883 (TLS)
- ใช้ username/password ของ MQTT
- ในซอร์สโค้ดสาธารณะใช้ค่า placeholder แทน credentials จริง

## 3.6 การออกแบบซอฟต์แวร์ฝั่งหลังบ้าน (Node-RED)

ไฟล์ flow: `node-red/flows_final_8.3v.json`

### 3.6.1 ฟังก์ชันหลัก
1. Subscribe MQTT ทั้ง 3 topics
2. เก็บค่าล่าสุดใน flow context
3. ทำงานเป็นรอบทุก 1 วินาทีเพื่ออัปเดตตัวชี้วัด
4. คำนวณ Availability, Performance, Quality และ OEE
5. ตรวจ Watchdog 60 วินาที เพื่อกำหนดสถานะ RUNNING/IDLE
6. บันทึกลง InfluxDB และส่งไปแสดงผล UI

### 3.6.2 สูตรที่ใช้ในระบบ

**Quality**
\[
Quality = \frac{good}{total} \times 100
\]

**Availability**
\[
Availability = \frac{runningTime}{totalPlannedTime} \times 100
\]

**Performance**
- Ideal Cycle Time = 5 วินาที/ชิ้น
- Expected Output = runningTime / 5
- Performance = (total / expectedOutput) × 100

**OEE**
\[
OEE = Availability \times Performance \times Quality
\]

## 3.7 การออกแบบฐานข้อมูลและ Dashboard

### 3.7.1 InfluxDB
- Bucket: `conveyor_oee`
- Measurement: `oee_metrics`
- ตัวอย่างฟิลด์: `total`, `good`, `waste`, `status`, `availability`, `performance`, `quality`, `oee`, `running_time_sec`, `total_time_sec`
- ตัวอย่าง tag: `conveyor_id = LINE_01`

### 3.7.2 Grafana
ไฟล์ dashboard:
`grafana/Smart Conveyor Belt - IIoT OEE Dashboard-1785916197192.json`

กลุ่มแผงแสดงผลหลัก:
1. สถานะเครื่องและ Running Time
2. เกจ OEE / Availability / Performance / Quality
3. ยอด Total / Good / Waste
4. กราฟแนวโน้มการผลิต

## 3.8 ขั้นตอนติดตั้งระบบ

1. ตั้งค่า Wi-Fi และ MQTT ใน firmware แล้วอัปโหลดลง ESP32
2. เปิด Node-RED ที่พอร์ต 1880 แล้วนำเข้า flow
3. ตั้งค่า MQTT broker และ InfluxDB ให้ตรงกับสภาพแวดล้อมจริง
4. สร้าง bucket `conveyor_oee` ใน InfluxDB (พอร์ต 8086)
5. นำเข้า dashboard ใน Grafana (พอร์ต 3000)
6. ทดสอบการนับชิ้นงานและการอัปเดตกราฟ

รายละเอียดเพิ่มเติมอยู่ใน `README.md` ของโปรเจค

## 3.10 สรุปบทที่ 3

วิธีการดำเนินงานของโปรเจคครอบคลุมตั้งแต่การออกแบบสถาปัตยกรรม การพัฒนาฮาร์ดแวร์และซอฟต์แวร์ ไปจนถึงการเชื่อมต่อฐานข้อมูลและ Dashboard โดยยึดหลักแยกชั้นระบบให้ชัดเจน เพื่อให้บำรุงรักษาและสาธิตได้ง่ายในระดับการศึกษา
