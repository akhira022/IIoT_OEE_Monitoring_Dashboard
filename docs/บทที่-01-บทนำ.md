# บทที่ 1 บทนำ

## 1.1 ความเป็นมาและความสำคัญของปัญหา

ในกระบวนการผลิต โดยเฉพาะสายพานลำเลียง การติดตามประสิทธิภาพเครื่องจักรยังมักอาศัยการจดบันทึกด้วยมือหรือสเปรดชีต ทำให้เกิดช่องว่างของข้อมูล เช่น

1. ไม่ทราบสถานะเครื่องแบบเรียลไทม์ว่ากำลังทำงานหรือหยุดอยู่
2. ไม่สามารถแยกสาเหตุของประสิทธิภาพต่ำได้ชัดว่าเกิดจากความพร้อมของเครื่อง ความเร็วการผลิต หรือคุณภาพชิ้นงาน
3. ข้อมูลย้อนหลังกระจัดกระจาย วิเคราะห์แนวโน้มได้ยาก
4. ผู้ควบคุมงานตัดสินใจเชิงรุกได้ช้า เพราะไม่มี Dashboard รวมศูนย์

แนวคิดอุตสาหกรรม 4.0 และ Industrial Internet of Things (IIoT) ชี้ให้เห็นว่าการเชื่อมเซนเซอร์หน้างานเข้ากับระบบประมวลผลและแสดงผล จะช่วยให้มองเห็นสถานะการผลิตได้ทันที และใช้ตัวชี้วัดมาตรฐานอย่าง Overall Equipment Effectiveness (OEE) เพื่อประเมินประสิทธิผลโดยรวมของเครื่องจักรได้อย่างเป็นระบบ

ด้วยเหตุนี้ ผู้จัดจึงพัฒนาโปรเจค **ระบบตรวจสอบประสิทธิภาพสายพานลำเลียงอัจฉริยะแบบเรียลไทม์ด้วยสถาปัตยกรรม IIoT และดัชนี OEE** โดยใช้ ESP32 ร่วมกับเซนเซอร์อินฟราเรด ส่งข้อมูลผ่าน MQTT ไปประมวลผลที่ Node-RED จัดเก็บใน InfluxDB และแสดงผลบน Grafana เพื่อเป็นต้นแบบระบบมอนิเตอร์ที่เหมาะกับการศึกษาและห้องปฏิบัติการ

## 1.2 วัตถุประสงค์ของโปรเจค

1. เพื่อออกแบบและสร้างแบบจำลองสายพานที่สามารถนับชิ้นงาน Total, Good และ Waste ได้
2. เพื่อส่งข้อมูลเซนเซอร์แบบเรียลไทม์ผ่านโปรโตคอล MQTT อย่างปลอดภัยด้วย TLS
3. เพื่อคำนวณดัชนี OEE จาก Availability, Performance และ Quality บนระบบหลังบ้าน
4. เพื่อตรวจจับสภาวะเครื่องหยุด (IDLE) อัตโนมัติเมื่อไม่มีชิ้นงานไหลผ่านเกินเวลาที่กำหนด
5. เพื่อจัดเก็บข้อมูลอนุกรมเวลาและแสดงผลผ่าน Dashboard มาตรฐานอุตสาหกรรม
6. เพื่อจัดทำเอกสารระบบและแนวทางติดตั้งให้สามารถทำซ้ำและขยายผลทางการศึกษาได้

## 1.3 ขอบเขตของโปรเจค

### 1.3.1 ขอบเขตด้านฮาร์ดแวร์
- ใช้ไมโครคอนโทรลเลอร์ ESP32
- ใช้เซนเซอร์อินฟราเรดจำนวน 3 ตัว สำหรับนับ Total, Good และ Waste
- เป็นชุดสาธิตสายพานขนาดเล็ก ไม่ครอบคลุมเครื่องจักรโรงงานจริงทั้งไลน์

### 1.3.2 ขอบเขตด้านซอฟต์แวร์
- Firmware บน ESP32 สำหรับอ่านเซนเซอร์และส่ง MQTT
- Node-RED สำหรับตรรกะคำนวณ OEE และ Watchdog
- InfluxDB v2 สำหรับจัดเก็บข้อมูล time-series
- Grafana สำหรับแสดงผล Dashboard

### 1.3.3 ขอบเขตด้านฟังก์ชัน
- คำนวณและแสดงค่า Availability, Performance, Quality และ OEE
- เปลี่ยนสถานะเป็น IDLE เมื่อไม่มีชิ้นงานผ่านเกิน 1 นาที
- แสดงยอดนับและแนวโน้มการผลิตแบบเรียลไทม์

### 1.3.4 สิ่งที่อยู่นอกขอบเขต
- ระบบคัดแยกของเสียด้วยกล้องหรือปัญญาประดิษฐ์
- การเชื่อมต่อ PLC อุตสาหกรรมโดยตรง
- ระบบสิทธิ์ผู้ใช้หลายระดับและการแจ้งเตือนองค์กรแบบสมบูรณ์
- การรับรองมาตรฐานความปลอดภัยไซเบอร์ระดับโรงงานจริง

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. ได้ระบบต้นแบบสำหรับมอนิเตอร์ประสิทธิภาพสายพานด้วยดัชนี OEE
2. นักศึกษาและผู้เรียนเข้าใจสถาปัตยกรรม IIoT แบบครบวงจร
3. สามารถใช้เป็นสื่อการเรียนการสอนในห้องปฏิบัติการได้
4. เป็นพอร์ตโฟลิโอที่แสดงทักษะทั้งฮาร์ดแวร์และซอฟต์แวร์สำหรับเข้าสู่สายงานช่างเทคนิค/IoT
5. เป็นฐานตั้งต้นสำหรับการพัฒนาต่อ เช่น การแจ้งเตือน และการรองรับหลายสายการผลิต

## 1.5 กลุ่มเป้าหมาย

| กลุ่มเป้าหมาย | การนำไปใช้ |
| --- | --- |
| นักศึกษา ปวส. สาขาอิเล็กทรอนิกส์ / เมคคาทรอนิกส์ / IoT | โปรเจคจบและชุดฝึกปฏิบัติ |
| อาจารย์ที่ปรึกษาและกรรมการสอบ | ประเมินความรู้ ทักษะ และการสาธิตระบบ |
| ผู้เรียนวิชา IIoT / Automation | กรณีศึกษา Sensor → Cloud → Dashboard |
| ห้องปฏิบัติการหรือโรงงานขนาดเล็ก | ต้นแบบระบบมอนิเตอร์ราคาประหยัด |

## 1.6 นิยามศัพท์เฉพาะ

| คำศัพท์ | ความหมายในโปรเจคนี้ |
| --- | --- |
| OEE | ดัชนีประสิทธิผลโดยรวมของเครื่องจักร |
| Availability | สัดส่วนเวลาที่เครื่องพร้อมทำงานจริง |
| Performance | สมรรถนะการผลิตเทียบกับรอบเวลาอุดมคติ |
| Quality | สัดส่วนชิ้นงานดีต่อชิ้นงานทั้งหมด |
| MQTT | โปรโตคอลสื่อสารเบาสำหรับงาน IoT |
| Watchdog | กลไกจับเวลาเมื่อไม่มีชิ้นงานผ่าน เพื่อเปลี่ยนสถานะเป็น IDLE |
| IDLE | สภาวะเครื่องไม่มีการไหลของชิ้นงานตามเงื่อนไขเวลา |

## 1.7 สรุปบทที่ 1

บทนี้กล่าวถึงปัญหาการติดตามประสิทธิภาพสายพานแบบดั้งเดิม เหตุผลที่ต้องพัฒนาระบบ IIoT ร่วมกับดัชนี OEE รวมถึงวัตถุประสงค์ ขอบเขต ประโยชน์ กลุ่มเป้าหมาย และนิยามศัพท์ เพื่อเป็นกรอบในการออกแบบและดำเนินงานในบทต่อไป
